# Фикстуры распознавания

Размеченные фотографии счётчиков для подбора модели утилитой
`tools/WaterCounters.Recognition.Bench`.

Сами фотографии в репозиторий не попадают (`.gitignore`): на них видны серийные
номера, а сами показания привязаны к конкретному адресу. Здесь лежит только
описание формата.

## Имя файла

```
<ключ счётчика>_<ожидаемое значение>_<серийный номер>.jpg
```

Например:

```
cold-water-kitchen_01234.567_11-111-111.jpg
hot-water-bathroom_00456.789_44-444-444.jpg
electricity_004521.3_55-555-555.jpg
```

* **Ключ счётчика** — тот же, что в `/config/settings.json`: строчные буквы, цифры
  и дефисы. Регистр важен: `IMG_1234.jpg` намеренно не считается разметкой, иначе
  снимок прямо с камеры молча превратился бы в «ожидаемое значение 1234».
* **Ожидаемое значение** — ровно как на барабане, с ведущими нулями. Из него же
  берётся разрядность счётчика: `01234.567` это 5 целых разрядов и 3 дробных.
  Поэтому фикстура самодостаточна и настроек не требует.
* **Серийный номер** — необязателен. Если указан, замер заодно считает долю верно
  прочитанных номеров.

## Сколько нужно

Критерий готовности — 95 % точных совпадений по целой части. На пяти снимках это
число ничего не значит: одна ошибка даёт 80 %. Разумный минимум — пара десятков,
по всем счётчикам и в разных условиях: день, вечер со вспышкой, блик на стекле.

Отдельно ценны барабаны в перекате, когда видны две цифры сразу: именно на них
модели ошибаются чаще всего, и именно этот случай отдельно оговорён в промпте.

Каждая неверно распознанная фотография добавляется сюда и становится
регрессионным тестом.

## Проверить, что файлы разобраны

```powershell
dotnet run --project tools/WaterCounters.Recognition.Bench
```

Утилита напечатает число найденных фикстур — или скажет, что размеченных фикстур
нет, если имена не подошли под схему.
