# HomeWaterCounters

Гибридное приложение для передачи показаний счётчиков воды и электричества.
Две части, связанные **только через папку Dropbox** — без своего сервера, без FCM,
без публичных эндпоинтов.

* **Мобильное (.NET MAUI, Android)** — съёмка счётчиков, загрузка фото, напоминания,
  подтверждение распознанных значений, единственная точка настройки обеих частей.
* **Десктопное (Windows, .NET 8)** — распознавание фото локальной VLM-моделью на GPU,
  прогноз при отсутствии фото, автоматический ввод в личный кабинет через Playwright,
  письмо на почту.

Участие человека сведено к двум действиям: сфотографировать счётчики и подтвердить
на телефоне то, что распознала модель.

## Архитектура

```
┌──────────────────────────┐          ┌─────────────────────────────┐
│  Android (MAUI)          │          │  Windows Desktop (WPF+Host) │
│  съёмка фото             │          │  DropboxWatcher (longpoll)  │
│  локальные уведомления   │          │  MessageProcessor           │
│  экран подтверждения     │          │  IMeterRecognizer → VLM/GPU │
│  ВСЕ настройки           │          │  IPortalAdapter (Playwright)│
│  offline-очередь (SQLite)│          │  Forecaster, Mailer         │
└───────────┬──────────────┘          └──────────────┬──────────────┘
            │                                        │
            └──────────────► Dropbox App Folder ◄─────┘
                    /config  /photos  /queue  /state
```

Dropbox используется не как хранилище, а как **очередь сообщений с состоянием**.
Жизненный цикл задачи: `pending → processing → done | failed`. Переход в `processing`
делается атомарным `MoveV2`, поэтому одну задачу не могут забрать два обработчика,
а файл, оставшийся в `processing` после падения процесса, — это ровно то, что нужно
переобработать при следующем запуске.

## Сборка и тесты

```powershell
dotnet build WaterCounters.sln
dotnet test  WaterCounters.sln
```

Браузер для тестов адаптера кабинета скачивается автоматически при первом
`dotnet test` — отдельная команда не нужна. Если хочется получить его заранее
(например, до отключения от сети), можно сделать это вручную после сборки:

```powershell
tests/WaterCounters.Portal.Tests/bin/Debug/net8.0/playwright.ps1 install chromium
```

## Настройка Dropbox

App key в репозитории не хранится. Перед первой сборкой укажите свой — одним из способов:

```powershell
# вариант 1: локальный файл (в .gitignore)
Copy-Item dropbox.local.props.example dropbox.local.props
# и подставить ключ внутри

# вариант 2: переменная окружения
$env:WATERCOUNTERS_DROPBOX_APP_KEY = 'ваш-ключ'
```

Ключ подставляется в константу на этапе сборки: на Android переменных окружения нет,
и передать его в рантайме иначе нельзя. Без настроенного ключа сборка проходит,
а при первом обращении возникает внятная ошибка.

Дальше:

```powershell
dotnet run --project tools/WaterCounters.DropboxSetup -- login
dotnet run --project tools/WaterCounters.DropboxSetup -- smoke
```

`login` проводит авторизацию по OAuth 2.0 Authorization Code + PKCE и кладёт
refresh-токен в `%LOCALAPPDATA%\WaterCounters\dropbox-token.dat` под DPAPI —
файл читается только той же учётной записью Windows на той же машине.

`smoke` прогоняет боевые операции в папке приложения и проверяет свойства, на которых
держится очередь: конфликт при повторной записи вместо автопереименования, атомарность
`MoveV2`, реакцию longpoll и полный цикл сообщения с дедупликацией.

В консоли приложения Dropbox должны быть указаны redirect URI `http://localhost:53682/oauth`
(для десктопа) и `wc-app://auth` (для мобильного), а также разрешения
`files.metadata.read`, `files.content.read`, `files.content.write`.

## Требования

* .NET SDK 8.0.4xx (версия зафиксирована в `global.json`)
* Для мобильной части: workload `maui-android` и **JDK 21**
  (пакет net8 принимает 11.0…21.0.99, поэтому OpenJDK 25 будет отвергнут)
* Для распознавания: NVIDIA GPU с compute capability ≥ 5.0 и от 8 ГБ VRAM,
  плюс Ollama или любой OpenAI-совместимый VLM-сервер

## Заметки о безопасности

* **App key Dropbox** в репозитории не хранится: значение приходит из
  `dropbox.local.props` или переменной окружения и подставляется в константу на этапе
  сборки. При потоке PKCE ключ не является секретом в криптографическом смысле — он
  неизбежно попадает в собранное приложение, а защиту даёт code_verifier, — но он
  идентифицирует конкретное приложение, поэтому публиковать его незачем.
  App secret не используется вовсе.
* **Секреты кабинета и SMTP** шифруются AES-256-GCM с ключом из PBKDF2-SHA256
  (600 000 итераций) перед записью в Dropbox; заголовок входит в associated data,
  поэтому подмена числа итераций ломает проверку так же, как подмена шифротекста.
* **Фотографии счётчиков** в репозиторий не попадают: они содержат серийные номера
  и привязаны к конкретному адресу.
